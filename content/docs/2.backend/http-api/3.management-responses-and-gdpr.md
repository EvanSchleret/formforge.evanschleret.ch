### Auto-publish on create and patch

Management create and patch support an optional boolean query parameter:

- `auto_publish`
- alias: `autoPublish`

Supported endpoints:

- `POST /api/formforge/v1/forms`
- `PATCH /api/formforge/v1/forms/{key}`

Behavior:

- if `auto_publish=true`, FormForge publishes immediately after create or patch
- the HTTP response returns the published revision

Create example:

```json
{
  "title": "Contact",
  "fields": [
    { "type": "text", "name": "full_name", "required": true },
    { "type": "text", "name": "email", "required": true }
  ]
}
```

Request:

- `POST /api/formforge/v1/forms?auto_publish=true`

Patch example:

```json
{
  "title": "Contact v2",
  "conditions": []
}
```

Request:

- `PATCH /api/formforge/v1/forms/{key}?auto_publish=true`

Without this parameter (or with `false`), behavior remains unchanged and returns a draft/non-published revision.

## Question statistics

Use `GET /forms/{key}/statistics` to aggregate submissions for one immutable form revision. The endpoint belongs to the management group, so it uses the management authentication and authorization settings. It also supports the `management.statistics` ability and the `management_statistics` method on a policy.

The `version` query parameter is required. Optional filters are:

| Parameter | Values | Default | Description |
| --- | --- | --- | --- |
| `from` | Date or date-time | Earliest matching submission | Inclusive start of the reporting period. A date-only value starts at midnight in the selected timezone. |
| `to` | Date or date-time | Latest matching submission | Inclusive end of the reporting period. A date-only value ends at 23:59:59 in the selected timezone. |
| `granularity` | `day`, `week` | `day` | Group the submission and question series by day or week. Weeks start on Monday. |
| `timezone` | PHP timezone identifier | `app.timezone` | Interpret date-only filters and build the series in this timezone. |
| `is_test` | Boolean | `false` | Include test submissions when `true`; otherwise include live submissions. |

For example:

```http
GET /api/formforge/v1/forms/customer-survey/statistics?version=3&from=2026-01-19&to=2026-01-25&granularity=week&timezone=Europe%2FZurich
```

The response contains the form key and revision, the applied filter settings, a submission total, a time series, and one aggregate for each field in that revision. The `period.from` and `period.to` values remain `null` when their corresponding date bounds are omitted; in that case, the series spans the first and last matching submissions. If there are no matching submissions and no date bounds, the series is empty.

Each question includes `eligible_count`, `answered_count`, and `response_rate`. A submission is eligible for a question only when that field is visible after conditional logic is resolved. An answer is counted when its value is not empty; `false` and `0` count as answers. `response_rate` is `answered_count / eligible_count * 100`, rounded to two decimal places, and is `0` when there are no eligible submissions.

The `summary.kind` value identifies the aggregate returned for a field:

| Kind | Field types | Aggregate |
| --- | --- | --- |
| `text` | `text`, `textarea`, `email` | Answer count and minimum, average, and maximum character length. |
| `number` | `number` | Numeric answer count and minimum, average, and maximum value. |
| `choice` | `radio`, `select`, `select_menu`, `checkbox`, `consent`, `switch` | Count and percentage for each configured choice. |
| `multiple_choice` | `checkbox_group` | Count and percentage for each choice, plus the total number of selections. A respondent can select more than one choice, so percentages can add up to more than 100%. |
| `temporal` | `temporal` | Count and percentage by month for date values, or by hour for time values. |
| `address` | `address` | Number of fully populated addresses and eligible, answered, and response-rate counts for each visible address part. |
| `file` | `file` | Number of files, total size, and average size in bytes. |
| `count` | Other field types | Answer count. |

The top-level `series` contains submission counts. Each question's `series` contains the same question-level counts and aggregate for every period. Both series use period keys such as `2026-01-15` for a day or `2026-W03` for a week.

The endpoint returns aggregates only. It does not return text or email values, address values, file names, or file contents. Its per-question response rate measures answers among submissions where the question was visible; it does not measure form views, starts, or invitation conversion.
