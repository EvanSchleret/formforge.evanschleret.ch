title: Runtime Client
description: Use the client API directly for imperative non-composable integrations.
---

Use the runtime client directly when you want to call endpoints without composable state wrappers.

For a ready-made settings screen backed by the runtime client, use [`FormForgeSettings`](/docs/client/components/formforge-settings). Its composable, `useFormForgeSettings`, is also exported for custom settings interfaces.

## Main method groups

### Schema and resolve

- `getAccessStatus(key, options?)`
- `createAccessChallenge(key, options?)`
- `verifyAccessChallenge(key, challengeId, code, options?)`
- `getForm(key, options?)`
- `getFormVersions(key, options?)`
- `getFormVersion(key, version, options?)`
- `resolveForm(key, input?, options?)`

For protected forms, pass the returned `access_token` as `accessToken` in the request options for `getForm`, `resolveForm`, upload, and submission methods. The token is sent in `X-FormForge-Access-Token`; keep it in memory until its `expires_at` value. Draft endpoints retain their normal authentication and do not accept this capability.

```ts
const status = await client.getAccessStatus('customer-survey')

if (status.data.required) {
  const challenge = await client.createAccessChallenge('customer-survey')
  const authorization = await client.verifyAccessChallenge(
    'customer-survey',
    challenge.data.challenge_id,
    enteredCode
  )
  const schema = await client.getForm('customer-survey', {
    accessToken: authorization.data.access_token
  })
}
```

- `listResponses(key, query?, options?)`

### Statistics

- `getFormStatistics(key, query, options?)`

The query requires a form `version` and accepts the same date, granularity, timezone, and test-submission filters as the [statistics endpoint](/docs/backend/http-api/management-responses-and-gdpr). The method returns `FormForgeStatisticsResponse`.
