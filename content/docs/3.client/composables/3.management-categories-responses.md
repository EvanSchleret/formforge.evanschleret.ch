## `useFormForgeManagement`

```ts
const management = useFormForgeManagement({
  scope: 'user'
})

const formsList = await management.listForms(false, {
  filters: {
    category: 'survey',
    search: 'contact'
  }
})

await formsList.refresh()
```

Methods:

- `listForms(includeDeleted?, options?)`
- `listFormRoute(routeKey, options?)`
- `refreshForms()` / `refresh()` (global fallback list refresh)
- `createForm(input, options?)`
- `patchForm(key, input, options?)`
- `publishForm(key, options?)`
- `unpublishForm(key, options?)`
- `deleteForm(key, options?)`
- `getRevisions(key, includeDeleted?, options?)`
- `getDiff(key, fromVersion, toVersion, options?)`

State:

- `forms`
- `loading`
- `error`
- `clientError`
- `fieldErrors`
- `businessErrorCode`
- `hasCategoryValidationError`

`listForms()` and `listFormRoute()` return:

- `data`: `FormForgeManagementForm[]`
- `refresh()`: re-run the same list request context

### Auto-publish payload support

`createForm` and `patchForm` accept both:

- `auto_publish`
- `autoPublish`

Outgoing payloads are normalized to `auto_publish`.

Create example (`POST /forms` with `auto_publish: true`):

```ts
await management.createForm({
  title: 'Contact',
  fields: [
    { type: 'text', name: 'full_name', required: true }
  ],
  autoPublish: true
})
```

Patch example (`PATCH /forms/{key}` with `auto_publish: true`):

```ts
await management.patchForm('form-key', {
  title: 'Contact v2',
  auto_publish: true
})
```

## `useFormForgeCategory`

```ts
const categories = useFormForgeCategory({
  immediate: true,
  initialQuery: {
    per_page: 20,
    is_active: true
  }
})
```

Methods:

- `listCategories(query?, options?)`
- `listCategoryRoute(routeKey, query?, options?)`
- `getCategory(categoryKey, options?)`
- `createCategory(input, options?)`
- `patchCategory(categoryKey, input, options?)`
- `deleteCategory(categoryKey, options?)`
- `refresh(options?)`

## `useFormForgeStatistics`

Use `useFormForgeStatistics` to request aggregate statistics for a specific form revision. The query requires `version`; it can also include date bounds, a `day` or `week` granularity, a timezone, and the `is_test` flag.

```ts
const statistics = useFormForgeStatistics({
  key: 'customer-survey',
  query: {
    version: '3',
    from: '2026-01-01',
    to: '2026-01-31',
    granularity: 'week',
    timezone: 'Europe/Zurich'
  }
})

await statistics.refresh({
  version: '3',
  from: '2025-12-01',
  to: '2025-12-31',
  granularity: 'day',
  timezone: 'Europe/Zurich'
})
```

The composable loads immediately by default. Set `immediate: false` to wait before making the first request. Its returned state includes:

- `statistics`: the `FormForgeStatisticsResponse`, or `null` before a successful request
- `loading` and `error`
- `fetchStatistics(query?, options?)` and `refresh(query?, options?)`

Question summaries contain aggregates only. For example, text and email answers expose length statistics rather than their contents. The response rate is calculated among submissions where each question was visible; it is not a form-view or invitation conversion rate. See the [backend statistics endpoint reference](/docs/backend/http-api/management-responses-and-gdpr) for filters, response fields, and aggregate types.
