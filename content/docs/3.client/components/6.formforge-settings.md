---
title: FormForgeSettings
description: Edit a form's management settings on a page separate from the schema builder.
---

`FormForgeSettings` loads a form through the FormForge client, reads code-protection status from the management resource when available, and saves changed settings with one explicit PATCH. It uses the same settings interface as the `Settings` tab in `FormForgeBuilder`.

```vue
<FormForgeSettings
  form-key="customer-survey"
  endpoint="/api/formforge/v1"
  locale="fr"
/>
```

Pass either `formKey` or `formUuid`. The component also accepts `scope`, `endpoint`, `locale`, an existing `client`, or `clientConfig`:

```vue
<FormForgeSettings
  :form-uuid="formUuid"
  :scope="{ prefix: '/api/teams/12/formforge/v1', params: {} }"
  :client-config="{ baseURL: 'https://api.example.test' }"
  locale="fr"
/>
```

The form identifier and connection props follow the builder and runtime client contract. The connected account needs permission to read the schema and update the management form.

## Settings and save behavior

The component edits the title, category, publication and closing dates, response limit, submission access, submission-code protection, pre-render access-code protection, draft availability, and the `api` settings already stored on the form. It keeps edits local until the user selects **Save**. The component sends one PATCH containing only changed top-level settings; it does not include `pages`, `fields`, or `conditions`.

The backend creates one revision per PATCH. Nested `api` and `drafts` objects are replaced as complete objects, so the component sends the complete current object whenever one of them changes. Unknown keys inside `api` are preserved.

Neither code is returned by the API. The component shows whether each protection is active and leaves its input blank. Saving unrelated settings keeps existing codes. Enter a new code to replace it, or disable its protection to remove it. Submission-code protection still applies only to response submission; access-code protection gates schema retrieval and public form operations.

The component shows loading, saving, success, validation, and request error states. It also exposes typed `save()` and `reload()` methods through a component ref.

```vue
<script setup lang="ts">
import type { FormForgeSettingsExpose } from '@evanschleret/formforgeclient/runtime'

const settings = ref<FormForgeSettingsExpose | null>(null)

async function saveSettings(): Promise<void> {
  await settings.value?.save()
}
</script>

<template>
  <FormForgeSettings ref="settings" form-key="customer-survey" />
  <UButton @click="saveSettings">Save settings</UButton>
</template>
```
